# Project history

How the project got here, the decisions that shaped it, and the bugs that were
found and fixed along the way. The full working notes, session by session, are
in [history/PROJECT_LOG.md](history/PROJECT_LOG.md) (sessions 20–36) and
[history/PROJECT_LOG_ARCHIVE.md](history/PROJECT_LOG_ARCHIVE.md) (sessions 1–19).
They were written during development with the help of an AI assistant (Claude).

Some early statements in those logs turned out to be wrong and were corrected
later. Most importantly, the session 2 belief that nobody had used PubLayNet or
layout cues for dewarping was disproved by the full literature check in session
36. **Where the logs and the paper disagree, the paper and [RESULTS.md](RESULTS.md)
are authoritative.**

## Timeline

### September 2026 — design, data, training system (sessions 1–25)

1. **Approach** (sessions 1–2): a U-Net that predicts a dense flow field, rather
   than pixel-to-pixel image translation, trained on synthetic warps of
   PubLayNet pages. PubLayNet's layout boxes suggested the core idea, a loss
   that keeps text regions rectangular.
2. **Augmentation pipeline** (sessions 3–9). The warp physics went through
   several real bugs before it was right:
   - The first cylinder warp had `flow_y ≡ 0`, so it could never bow a text
     line. It was replaced with a 3-D cylinder and a pinhole camera.
   - Composing images by successive resampling blurred them and drifted from
     the labels. The fix composes the flows and resamples once; label error went
     from 4.9 grey levels to exactly 0.
   - 17 % of "warped" samples were accidental identities. Profiles became
     deterministic.
   - The amount of visible background revealed warp strength (corr −0.825).
     Random camera framing was added.
   - Edge smearing was replaced by real background compositing and a validity
     mask.
3. **Storage** (sessions 5, 10–11): the naive loose-file format projected to
   1.24 TB. It was redesigned as JPEG blobs plus float16 normalized flow memmaps
   (about 25 GB). The flow grid was set to 112×144 from a measured accuracy
   table.
4. **Annotations** (sessions 12–15): `train.json` was located and checked to
   align exactly with the local images. The layout store was built with a
   streaming COCO reader, after a naive one read 19 of 120,761 records.
5. **The layout-consistency loss** (session 14): a rigid shift costs 0.0000 and
   a bend with the same L1 costs about 2.28. That test is still in
   `test_layout_loss.py`.
6. **Dataset verified** (sessions 15–16): 145,313 samples, regenerated byte for
   byte from the manifest. The 234 landscape pages were excluded.
7. **Training system** (sessions 17–23):
   - The model was built, and it overfits a batch from 45.07 to 2.47 px.
   - Multi-session training is resumable; the restored state was proven bit-exact
     in a CPU test.
   - Several Kaggle traps were found and engineered around: mount paths that
     differ between notebooks, `datasets create` skipping subfolders, pinned
     dataset versions, and Save & Run All restarting the run.
   - The smoke test passed.
8. **Inference** (sessions 24–25): flow inversion, full-resolution
   rectification, and a local preview tool.

### September – October 2026 — the experiment (sessions 26–35)

9. **Layout arm, 30 epochs** (sessions 26–31): EPE 3.66 px on the full
   validation set (the do-nothing baseline is 39.88 px). Two measurement bugs were found and fixed:
   - The validation subset during training (480 samples) differs from the full
     validation set.
   - The preview's PSNR baseline moved with the model.
10. **Ablation** (sessions 32–34):
    - The layout metric is not logged when λ = 0, so it was computed offline
      from checkpoints for both arms.
    - The first comparison at about epoch 19 vs 18 already showed the pattern.
    - The final 30-vs-30 comparison: EPE is essentially tied (0.7 %) while
      layout distortion is about 6–7 % lower.
11. **OCR** (session 35):
    - At 448×576 even the true flow gives 66–71 % CER, so the test was redesigned
      as a 3× re-synthesis.
    - Result: the layout arm reads better, mostly on the hardest warps.

### October 2026 — paper (session 36)

12. **Real photos.** The official DocUNet MATLAB evaluation was ported to
    Octave, and its score on the raw photos reproduces the published one. With
    the system Tesseract (5.3.4) the OCR numbers did not match the literature,
    so Tesseract 5.0.1 was built from source; then they did.
    - Both arms improve the photos clearly, but they are indistinguishable from
      each other and far behind the state of the art.
13. **Literature verification.** Every reference was checked against a primary
    source. The checks showed that text-line and layout cues *have* been used
    before: ForCenNet, MataDoc, D2Dewarp and LA-DocFlatten. The paper's claims
    were narrowed accordingly.
14. **Review.** An independent review pass checked about 250 numbers. Its
    corrections are in the paper: the per-page vs batch-pooled 𝒞, sign
    conventions, softer real-photo claims, and the units of the loss.

## Decisions worth knowing about

| decision | reason |
|---|---|
| flow field, not image-to-image | sharp outputs; free exact labels from the synthetic warp |
| backward flow on the *input* grid | every loss is computed without inversion; invert once at inference |
| 448×576 input, 112×144 flow | keeps the US-Letter aspect; flow storage error 0.018 px at that grid |
| one T4, no `DataParallel` | the exact-resume proof was single-device; changing the effective batch mid-run would break the ablation |
| λ = 0.2, `global` banding, 24 bands | `global` is about 12× faster than per-region and also constrains side-by-side columns; a λ sweep is still open |
| 30 epochs, cosine over 540k steps | fits about 2 Kaggle sessions per arm within the weekly free quota |
| score both arms at step 531,990, not `best.pt` | `best.pt` is selected on the same validation set |
| per-page 𝒞 in the paper | it is the natural per-sample metric; the batch-pooled training-log value is a different statistic |
| Tesseract 5.0.1 for DocUNet | the version behind published numbers; the version shifts CER by about 0.025 |
